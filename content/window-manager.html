Bosio 창 관리자는 앱 표면을 구면 위치에 배치하고, 겹침·포커스·입력을 처리한 뒤 정이십면체 셀 장면을 만듭니다. OutputCore가 그 장면을 현재 자세로 화면에 투영합니다.

창과 IPC

데몬은 Unix 소켓 /tmp/bosio-wm.sock에서 JSON IPC를 받습니다. 앱은 클라이언트 API로 구면 각도 위치의 창을 만들고 RGB 표면을 전달하며 이벤트를 읽습니다. 여러 독립 프로세스의 창은 z 순서와 포커스로 관리됩니다. BoAYo SDK는 이 API를 감싸서 앱 창에 캡션 규칙을 붙입니다.

합성에서 출력 코어까지

앱 RGB24 표면구면 창 겹침C++/NEON 셀 합성RGB332 장면BPT1 또는 전체 갱신OutputCore

네이티브 C++ 합성기는 ARM NEON을 활용합니다. 창의 작은 영역이 바뀌면 AA 샘플 범위에 겹치는 dirty 셀만 재합성해 BPT1 패치를 보냅니다. 위치·크기·겹침이 바뀌거나 부분 갱신으로 아래 장면의 색을 정확히 보존하기 어려울 때는 전체 스냅샷을 보냅니다. 데몬이 최종 구면 장면의 소유자이므로 앱 프로세스가 전체 프레임버퍼를 점유하지 않습니다.

입력과 포커스

마우스 이벤트와 BTN2 시선 클릭은 같은 포인터 경로로 들어옵니다. 클릭 위치에서 가장 위의 창을 선택하고 이벤트를 해당 앱에 보냅니다. 유일한 BoAYo 런처 패널은 다른 앱 창보다 위에 놓이지만, 흰 패널 영역 밖을 클릭하면 패널만 접히고 해당 위치에 앱 창이 있으면 그 클릭도 전달됩니다. 기존 앱 창은 계속 남습니다.

장면 갱신 속도와 영상 속도

HDMI 픽셀 스트림의 프레임 속도와 앱 내용이 바뀌는 속도는 다릅니다. 고정된 장면은 출력 코어가 계속 다시 투영하며, 창의 변경 내용은 Bosio 합성과 전송이 끝날 때 반영됩니다. AA와 dirty tile 성능의 의미는 화질과 성능에서 설명합니다.
