FullStack 실행 절차

세 저장소와 통합 저장소, 자동 시작 서비스 및 업데이트 흐름입니다.

FullStack 저장소는 세 개발 저장소의 검증된 커밋을 서브모듈로 고정하고 PYNQ-Z2에 bitstream, Bosio 데몬, BoAYo 런처·SDK를 차례로 올립니다.

복제와 배포

git clone --recursive https://github.com/VARZero/bosio_FullStack.git
cd bosio_FullStack
python -m pip install -r requirements.txt

# Windows PowerShell
$env:BOSIO_PYNQ_HOST = "192.168.2.99"
$env:BOSIO_PYNQ_USER = "xilinx"
$env:BOSIO_PYNQ_PASSWORD = "<보드 비밀번호>"
python scripts/bosio_stack.py deploy-start
python scripts/bosio_stack.py status

IP 주소는 현재 테스트 보드의 예시이며 네 환경에 맞게 바꿀 수 있습니다. 암호는 환경 변수로만 넣고 소스·문서·Git 커밋에는 기록하지 않습니다. SSH 키 로그인도 지원합니다.

부팅 자동 시작

설치 후 bosio-window-manager.service가 구면 장면과 IPC를 맡고, 그 뒤 boayo-desktop.service가 런처 패널을 Bosio 창으로 등록합니다. 두 서비스는 systemd에서 부팅 자동 시작됩니다. 앱은 apps.json의 명령으로 별도 프로세스로 시작됩니다.

# 보드에서 직접 확인
systemctl is-active bosio-window-manager.service
systemctl is-active boayo-desktop.service
systemctl status bosio-window-manager.service boayo-desktop.service
journalctl -u bosio-window-manager.service -u boayo-desktop.service -n 100 --no-pager

문제가 있을 때 확인 순서

  1. SSH 접속과 두 서비스의 active 상태를 확인합니다.
  2. 통합 상태 출력에서 출력 코어 오류, 장면 유효성, 런처 등록을 확인합니다.
  3. 센서가 있다면 보정 완료와 패킷 수 증가를 확인합니다.
  4. HDMI 케이블과 캡처 장치 연결, 보드 출력 모드를 확인합니다.
  5. 런처가 없으면 BoAYo 서비스 로그를, 창 내용만 검정이면 앱 로그와 SDK 연결을 확인합니다.

새 RTL을 다시 빌드하는 절차는 현재 확인된 bitstream을 그대로 배포하는 이 빠른 경로와 다릅니다. OutputCore RTL과 SphericalWM 하드웨어 빌드 스크립트를 변경했다면 새 bitstream을 검증한 뒤 통합 배포를 갱신하세요. 통합 저장소의 README와 스크립트가 최신 실행 계약입니다.
